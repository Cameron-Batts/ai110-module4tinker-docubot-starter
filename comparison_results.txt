[AUTH.md]
## Environment Variables

The authentication system depends on two variables:

- `AUTH_SECRET_KEY`  
  A secret string used to sign all access tokens. Must be long and unpredictable.

- `TOKEN_LIFETIME_SECONDS`  
  Controls how long a generated token remains valid. Defaults to 3600 seconds if not set.

Both variables must be configured before starting the server.

---
[AUTH.md]
## Token Generation

Tokens are created by the `generate_access_token` function in the `auth_utils.py` module. The function takes a user ID and returns a signed JSON Web Token string.

Internally, the token is signed using the secret stored in the `AUTH_SECRET_KEY` environment variable. If the key is missing or empty, token creation will fail.

The token payload includes:

- `user_id`
- `issued_at`
- `expires_at`
- `permissions` (optional)

---
[AUTH.md]
## Validating Requests

Requests are validated by the `require_auth` decorator. This decorator ensures that:

1. A token is present in the Authorization header  
2. The token signature is valid  
3. The token has not expired  
4. The user has permission to access the requested resource  

If validation fails, the client receives a 401 Unauthorized response.

QUESTION: How does a client refresh an access token?

MODE 1: NAIVE
To refresh an access token, a client typically sends a request to the authorization server's **token endpoint** using the **Refresh Token** grant type. 

Here are the standard steps and requirements for the request:

### 1. The HTTP Request
The client makes a `POST` request to the token endpoint (usually over HTTPS). The request body must be URL-encoded (`application/x-www-form-urlencoded`) and include the following parameters:

*   `grant_type`: Must be set to `refresh_token`.
*   `refresh_token`: The refresh token that was previously issued to the client during the initial authentication flow.
*   `client_id`: The unique identifier of your application.
*   `client_secret`: (If required by the server for confidential clients) Your application's client secret.
*   `scope`: (Optional) The requested scope cannot include any new scopes that weren't granted in the original token (some servers allow you to request a *subset* of the original scopes).

**Example Request:**
```http
POST /oauth/token HTTP/1.1
Host: auth.example.com
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token&
refresh_token=r_secret_987654321&
client_id=my_application_id&
client_secret=my_client_secret
```

---

### 2. The Server Response

#### **Success Response (`200 OK`)**
If the refresh token is valid, the authorization server responds with a JSON object containing a new access token and, optionally, a new refresh token.

```json
{
  "access_token": "at_new_123456789",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "r_new_987654321" 
}
```
*Note: Some systems practice "refresh token rotation," meaning a brand-new refresh token is issued every time, and the old one is invalidated.*

#### **Error Response (`400 Bad Request` or `401 Unauthorized`)**
If the refresh token is expired, revoked, or invalid, the server will return an error response:

```json
{
  "error": "invalid_grant",
  "error_description": "The provided refresh token is expired or revoked."
}
```
**Handling Errors:** If you receive an invalid grant error, the client-side application must force the user to re-authenticate (i.e., redirect them to the login screen) because the session cannot be automatically renewed.

## Client Workflow

A typical client follows this sequence:

1. Send credentials to `/api/login`
2. Receive an access token in the response
3. Include the token in the Authorization header for all subsequent requests:

    ```plaintext
    Authorization: Bearer <token>
    ```

4. Refresh the token when it expires by calling `/api/refresh`

Clients should never store tokens in URL query parameters.

---
[API_REFERENCE.md]
### POST /api/refresh

Exchanges an existing valid token for a new one with an updated expiration time.

Headers:

    ```plaintext
    Authorization: Bearer <token>
    ```

Response:

    ```json
    {
    "access_token": "<new_token>"
    }
    ```
